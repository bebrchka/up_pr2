# Практическая работа 2. Каталог магазина одежды

Приложение-клиент магазина одежды на Flutter Web. Данные хранятся в памяти и
восстанавливаются при перезагрузке страницы. Реализованы две сущности:
**товар** (`ClothingItem`) и **бренд** (`Brand`) — аналог книги и автора из
методички.

## Запуск

```bash
flutter pub get
flutter run -d chrome
```

Проверки:

```bash
flutter analyze   # 0 замечаний
flutter test      # 13 тестов: репозитории, фильтры, пагинация, deleteMany, URL
```

## Схема слоёв

```
lib/
├── models/                 неизменяемые модели и параметры запроса
│   ├── clothing_item.dart  товар: copyWith, clearDeletedAt, isDeleted
│   ├── brand.dart          бренд: copyWith, clearDeletedAt, isDeleted
│   ├── category.dart       справочник категорий
│   ├── page_result.dart    PageResult<T>: items, page, size, total
│   ├── item_query.dart     условия отбора + разбор/сборка адреса
│   └── brand_query.dart    условия отбора брендов
├── data/seed_data.dart     начальный набор: 25 товаров, 10 брендов
├── repositories/           интерфейсы + реализации в памяти
│   ├── item_repository.dart / in_memory_item_repository.dart
│   └── brand_repository.dart / in_memory_brand_repository.dart
├── state/                  ChangeNotifier-состояние экранов
│   ├── item_list_notifier.dart / brand_list_notifier.dart
│   ├── item_details_notifier.dart / brand_details_notifier.dart
│   └── load_status.dart    idle / loading / success / error
├── screens/                экраны списков и карточек
├── widgets/                переиспользуемые виджеты
│   ├── entity_table.dart   EntityTable<T> и TableColumnSpec<T>
│   ├── responsive_entity_view.dart  таблица/карточки по ширине окна
│   ├── debounced_text_field.dart    задержка 400 мс
│   ├── pagination_bar.dart
│   ├── status_views.dart   загрузка / пусто / ошибка
│   └── confirm_dialog.dart
├── router.dart             go_router: /items, /items/:id, /brands, /brands/:id
└── main.dart               MultiProvider + MaterialApp.router
```

Направление зависимостей: `screens → state → repositories → models`.
Виджеты и экраны не обращаются к репозиторию: только `context.watch` /
`context.read` провайдера состояния. `setState` в проекте не используется.

## Условия отбора в адресе

Пример:

```
/items?search=джинсы&categoryId=2&brandId=3&priceFrom=1000&priceTo=7000&sort=year,desc&page=2&size=25&showDeleted=true
```

| Параметр        | Значение                                  |
|-----------------|-------------------------------------------|
| `search`        | название или артикул / название или страна |
| `categoryId`    | категория товара                          |
| `brandId`       | бренд                                     |
| `priceFrom/To`  | диапазон цены                             |
| `country`       | страна бренда                             |
| `yearFrom/To`   | диапазон года основания бренда            |
| `sort`          | `поле,asc` или `поле,desc`                |
| `page`, `size`  | страница и размер (10, 25, 50)            |
| `showDeleted`   | показывать удалённые                      |

Поток данных:

1. Маршрут разбирает `state.uri.queryParameters` в `ItemQuery`.
2. Экран сравнивает полученный запрос с запросом в notifier и вызывает
   `applyQuery` (после кадра, чтобы не менять состояние во время build).
3. Любое действие пользователя собирает новый `ItemQuery` и вызывает
   `context.go(query.toLocation())`.
4. Браузерная кнопка «назад» возвращает прежний адрес, экран снова
   синхронизируется с ним — состояние списка восстанавливается.

`copyWith` сбрасывает `page` на 1 при смене любого условия отбора. Для
сброса nullable-фильтров используется константа-маркер `_unset`, как и
`clearDeletedAt` в моделях.

## Ошибка в deleteMany из методички

Было:

```dart
final i = _books.indexWhere((b) => b.id == id && !b[i].isDeleted);
```

`b` — это одна книга (`Book`), а не список, поэтому `b[i]` не компилируется:
у класса `Book` нет `operator []`. Кроме того, индекс `i` в момент вычисления
предиката ещё не известен. Исправление:

```dart
final index = _items.indexWhere(
  (item) => item.id == id && !item.isDeleted,
);
```

Теперь `deleteMany` помечает только существующие неудалённые записи и
возвращает корректное количество. Повторный вызов для тех же id вернёт 0.
Это закреплено тестом `deleteMany исправлен`.

## Почему таблица обобщённая

`EntityTable<T>` принимает список `TableColumnSpec<T>`: подпись, поле
сортировки, выравнивание и функцию построения ячейки. Экран книг и экран
брендов отличаются только описанием колонок и набором действий, а не
копией разметки. Один и тот же виджет отвечает за:

- флажки множественного выбора и подсветку удалённых строк;
- сортировку по клику на заголовок со стрелкой в активной колонке;
- двумерную прокрутку (`SingleChildScrollView` по горизонтали внутри
  вертикальной прокрутки);
- колонку действий.

`ResponsiveEntityView<T>` добавляет адаптивность: при ширине меньше 600 px
показывает список карточек, иначе — таблицу. Оба экрана используют одни и
те же виджеты, поэтому при добавлении новых сущностей (жанры, издательства,
читатели) код таблицы не дублируется.

## Состояния экрана

- `loading` — индикатор и подпись «Загрузка данных…»;
- `error` — карточка ошибки с кнопкой «Повторить»; для демонстрации в
  AppBar есть кнопка с иконкой бага, включающая искусственный сбой;
- `success` с пустым списком — отдельный экран «Ничего не найдено»;
- `success` с данными — таблица или карточки.

Выделение очищается при смене условий отбора в `applyQuery`. Поиск
запускается через 400 мс после окончания ввода. Удаление выбранных, а также
физическое удаление требуют подтверждения.

## Соответствие критериям

- «3»: две модели с `copyWith`, репозитории в памяти (25 товаров, 10 брендов),
  слои, provider, экраны списка и карточки, go_router, четыре состояния,
  `flutter analyze` без замечаний.
- «4»: исправлен `deleteMany`; поиск по названию/артикулу и по
  названию/стране; фильтры «категория + бренд + цена» (для брендов — «страна +
  год основания»); множественное удаление с подтверждением; логическое и
  физическое удаление, показ удалённых и восстановление; раскладка
  переключается на 600 px.
- «5»: пагинация с размерами 10/25/50 и переходами на первую, предыдущую,
  следующую и последнюю страницы; сортировка по трём полям каждой сущности
  со стрелкой; `EntityTable<T>` для обеих сущностей; все условия в адресе;
  задержка поиска 400 мс.
